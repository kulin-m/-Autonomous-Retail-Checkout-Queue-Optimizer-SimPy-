How the agent learns

It starts knowing nothing, tries lanes, sees the cost of the queues that result, and updates a table of 216 states × 3 actions over 250 episodes.

Problem and method

Supermarket counters rarely serve at the same speed. Static or random assignment ignores this, so slower lanes back up while faster ones sit underused. The agent treats routing as a sequential decision problem and learns a dispatching policy purely from observed queue transitions, with no prior knowledge of arrival or service rates.

StateQueue lengths (q₀, q₁, q₂), each 0 to 5: 216 states.
ActionSend the arriving customer to lane 0, 1 or 2.
ServiceA lane clears one customer per step with probability 0.60, 0.40 or 0.30.
Reward−(q₀ + q₁ + q₂ + 0.5 × queue variance): penalises total waiting and uneven load.
UpdateQ(s,a) ← Q(s,a) + α [ r + γ · max Q(s′,·) − Q(s,a) ]

Assumptions and limits

  • One customer arrives per step; each lane clears at most one customer per step.
  • Service probabilities are fixed and the store has exactly three lanes.
  • Queues are capped at five, which keeps the state space small enough for a lookup table.
  • Results come from simulation, not from real store data.

Design notes

Why Q-learning and not a neural network?

With 216 states a table is enough and is easy to inspect. A neural network would matter once queue lengths or lane counts make the table too large.

Do I need a GPU?

No. Training takes a fraction of a second on a laptop; this page trains in your browser.

How do I run the original code?

pip install numpy matplotlib seaborn python-docx pygments, then python generate_q_learning_experiment.py. Plots land in q_learning_plots/.
